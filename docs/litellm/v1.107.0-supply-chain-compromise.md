# LiteLLM v1.107.0 supply-chain compromise

Upstream incident: [BerriAI/litellm#47826](https://github.com/BerriAI/litellm/issues/47826).

## What happened upstream

On 2026-10-21 the LiteLLM release pipeline built v1.107.0 from a lookalike
repository, `Berri-AI/litellm`, using stolen GitHub CLI tokens of three
maintainers. The PyPI wheels and every v1.107.0 Docker image (`litellm`,
`litellm-database`, `litellm-non_root`, on GHCR and Docker Hub) gained three
files in site-packages:

- `cook.pth` and `cook.py`: a credential stealer that runs on every Python
  start. With `DATABASE_URL` set it dumps `LiteLLM_CredentialsTable` and
  `LiteLLM_ProxyModelTable`, along with SSH keys, cloud credentials and the
  environment of every readable process, and posts them to
  `www.litellm.dev/healthcheck`.
- `sitecustomize.py`: an hourly loader that fetches and `exec()`s code from a
  domain named in a GitHub dead-drop.

`latest`, `main-latest` and `main-stable` pointed at the infected image from
about 11:48Z until upstream deleted them a few hours later.

## Impact on this deployment

The webhook deploy at 2026-10-21 14:41Z (commit `6217063`) failed with:

```
failed to solve: ghcr.io/berriai/litellm-database:main-stable: ... not found
```

The tag had already been deleted, so nothing infected was pulled. The running
container was built on 2026-10-11 from litellm 1.104.2. Checked on
2026-10-21 on miti-sg:

- no `cook.pth`, `cook.py` or root-level `sitecustomize.py` in site-packages
  (only the legitimate ones under `ddtrace/` and `opentelemetry/`);
- no `/tmp/.pc_*` marker and no `/tmp/remote_code_loader.lock`;
- no other litellm images on miti-sg, none on miti-jp.

No key rotation was needed.

## Fix

`litellm/Dockerfile` pins
`ghcr.io/berriai/litellm-database:v1.106.2@sha256:35f2cec3a14bb297e08bfab56c1fc377432bc4071aaf71978fdff043a5d91e79`.
The same digest is published as `docker.io/litellm/litellm-database:v1.106.2`,
for amd64 and arm64.

## Leaving the pin

Move back to `main-stable` once upstream:

1. publishes a post-mortem naming how the tokens were stolen and how the
   release pipeline was locked down, and
2. ships a release from that pipeline.

Before switching, check the new image's SLSA provenance names
`https://github.com/BerriAI/litellm` as the source, and look for
`cook.pth` in its site-packages.
